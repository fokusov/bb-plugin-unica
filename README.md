# bb-unica

Интеграция Unica с проектами 1С в BB. Плагин запускает официальный пакет Unica на машине окружения, предоставляет MCP-инструменты через `unica_call` и оставляет управление стадиями и приёмкой за BSL Flow.

Проверяемая линия первой версии — BB 0.50.1, Plugin SDK 0.6.157, Windows x64 и Unica 0.16.0. Готовые бинарные файлы и материалы Unica загружаются из её официального пакета. Исходный код этого репозитория распространяется по MIT.

## Установка и первый запуск

```powershell
bb plugin install git:https://github.com/fokusov/bb-plugin-unica.git@v0.1.0
bb unica status --project <ID>
bb unica prepare --project <ID>
bb unica tools --project <ID>
bb unica call unica.view --project <ID> --json
```

Вызов из треда выбирает его окружение. CLI вне треда принимает `--project` или `--environment`. Для неизвестного адреса первый вызов `unica.view` делается без аргументов. Текущие имена и схемы возвращает `bb unica tools`.

Для сборки из локального checkout выполните `bb plugin install .` в корне репозитория.

## Диагностика

Откройте **Настройки → Установленные плагины → Unica → Диагностика Unica**, выберите проект и при необходимости рабочее окружение. Форма показывает каталог, версию пакета и состояние рантайма. Кнопка **Проверить MCP** получает свежий каталог MCP и вызывает `unica.view` для чтения выбранных исходников. Каталог перечисляет инструменты, объявленные MCP, а результат функциональной проверки относится к `unica.view`.

`bb unica skills --environment <ID>` из пользовательского терминала подключает официальные навыки и справочники в `.bb/skills` и `.bb/references` выбранной копии, сохраняя существующие файлы. Свой список добавленных файлов плагин хранит в `.bb/unica-skills.json`. Если в агенте включён нативный MCP Unica, отключите для этого профиля лишний маршрут, чтобы агент использовал политику BB.

## Доступ и переход

Политика хранится в `.bb/unica.json` основного источника проекта. До её сохранения действует прежнее значение `unicaPolicy`, записанное в `.bb/1c-project.json` или `.dsh/1c-project.json`. В отсутствие настройки действует `ask`. Политика `read` запрещает запись, `ask` требует отдельного подтверждения, `allow` пропускает обычную запись. Исполнение плана `unica.apply` требует подтверждения и при `allow`.

Для совместной работы используйте сборку `1c-properties` с настройкой `unicaMode`. Завершите текущие задачи. На каждой машине, где использовалась встроенная Unica, выполните `bb 1c-properties unica debug stop <проект>` и `bb 1c-properties unica stop <проект>`. Затем примените внешний режим:

```powershell
bb plugin config 1c-properties set unicaMode external
bb plugin reload 1c-properties
bb plugin reload bb-unica
bb unica status --project <ID>
bb unica policy --project <ID>
```

Если включён старый выпуск `1c-properties` без внешнего режима, `bb-unica` приостанавливает свои инструменты. Перезагрузка панели применяет настройку к регистрации инструментов. Перезагрузка `bb-unica` включает его инструменты после передачи.

Для отката завершите операции, остановите DAP через `bb unica debug stop --environment <ID>` и MCP через `bb unica stop` на каждой использованной машине. Затем выполните `bb plugin disable bb-unica`, выставьте `unicaMode embedded` и перезагрузите `1c-properties`. Совместимая панель применит политику, сохранённую в `.bb/unica.json`. Для новой DAP-сессии встроенная Unica использует параметры базы панели.

## Отладка

`bb unica debug start --port <PORT>` подключается к существующему локальному серверу отладки. `bb unica debug stop` завершает сессию плагина. Для `debug launch` задайте явную тестовую FILE-базу и платформу в `.bb/unica.json` выбранной рабочей копии.

```json
{
  "debug": {
    "platformPath": "C:/1C/8.3.27/bin",
    "infobasePath": "C:/Sandbox/DebugBase"
  }
}
```

Из треда BB запрашивает подтверждение через форму. В терминале вне треда для операции, которая требует подтверждения, передайте `--approved` после проверки выбранного контура. Клиент и сервер, запущенные плагином, относятся к одной сессии.

## Проверки и происхождение

```powershell
npm ci
npm run check
bb plugin build .
npx tsx scripts/smoke.ts
```

Мост MCP, классификация и DAP адаптированы из MIT-кода `bb-plugin-1c-properties`. Сценарий проверки разных рабочих деревьев основан на подходе [dsh-unica](https://github.com/malinovme/dsh-unica/blob/main/docs/native-verification.md). Файлы DSH-плагина и официального пакета Unica в репозиторий не включены.
