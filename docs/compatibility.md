# Контракт переноса Unica

Проверенная линия разработки: Windows x64, BB 0.50.1, SDK 0.6.157, Unica 0.16.0. Полный контур DAP проверяется на изолированной FILE-базе 1С 8.5.1.1529.

| Контракт | Перенос |
| --- | --- |
| Вызов MCP и список схем | Сохраняются `unica_call`, `unica_tools` и `unica_status`. Схемы приходят из официального процесса. |
| Рабочая копия | BB разрешает ID окружения треда. Путь передаётся в проверенном метаполе MCP. План и задача привязаны к каноническому пути. |
| Политика | Сохраняются `read`, `ask`, `allow`. Значение читается с основного источника, рабочая копия используется для операции. |
| CLI | Вместо префикса `bb 1c-properties unica` используется `bb unica`. Выбор среды задаётся по ID, JSON-аргументы принимаются с `--args` или `--args-file`. |
| DAP | Сохранены подключение, запуск тестового контура, команды, события и остановка. Настройки тестовой цели хранятся локально в рабочей копии. |
| Скиллы | Официальные файлы ставятся из пакета в рабочую копию. Существующие файлы сохраняются. |

Штатный BB и Agent Tools дают инфраструктуру регистрации и доставки навыков. Адаптер нужен для применения политики и маршрутизации каждого вызова по окружению. Проверка двух рабочих деревьев взята из методики DSH. Официальная Unica предоставляет bootstrap и manifest, которыми пользуется адаптер. Репозиторий адаптера сохраняет MIT-атрибуцию `1c-properties`. Код DSH и поставка Unica в Git не включаются.

## Проверка перехода и отката

Пара локальных сборок прошла проверку в отдельном профиле BB 0.50.1 на Windows x64. Для перехода требуется `1c-properties`, который сообщает применённый режим через RPC `unicaOwnership` версии 1. При активной панели без этого контракта `bb-unica` сохраняет свои инструменты отключёнными.

| Сценарий | Результат |
| --- | --- |
| Встроенный режим и установленный `bb-unica` | У панели 8 инструментов Unica, у отдельного плагина 0. Сохранение `external` до перезагрузки не передаёт владение. |
| Перезагрузка панели в `external`, затем `bb-unica` | У панели 0 инструментов Unica, у отдельного плагина 8. Панель сохранила `project_1c_params`, проверку версии BSL Flow и синхронизацию его навыков. |
| Работа после передачи | В двух Git worktree, подключённых в тестовом профиле отдельными проектами, `unica.view` открыл нужный каталог, `unica.search` прочитал маркер из его модуля. Старые навыки, справочники и параметры сохранены. |
| DAP | Обе интеграции запустили контур на временной FILE-базе и завершили процессы клиента, `dbgs` и DAP. После передачи `bb-unica` получил цели отладки. |
| Перезапуск BB | Внешний режим, единственный владелец Unica и заданная политика сохранились. |
| Внешний режим без активного `bb-unica` | Параметры 1С доступны, прежний RPC отладки отклоняет вызов, регистрации панели не возвращаются. |
| Откат | Ранний возврат в `embedded` заблокирован, пока `bb-unica` включён. После его отключения панель восстановила 8 инструментов, прочитала исходники и применила политику `read` из `.bb/unica.json`. Изменение политики из панели сохранило раздел `debug` и файл параметров 1С. |

### Проверка установок из Git-тегов

На BB 0.50.1 под Windows повторена проверка с чистым профилем и двумя локальными репозиториями. BB самостоятельно собрал и установил плагины из `git:` по тегам `v0.1.0`: `1c-properties` (`f41ba92a0ee52a75848bc65e7cea16a6b6de85eb`) и `bb-unica` (`7223102d75fbf4c10197a4fa5ec636863e338c98`). Проверены отдельная работа обоих плагинов, единственный владелец восьми инструментов BB при переключении, 11 инструментов MCP, чтение двух worktree, DAP на отдельной FILE-базе, перезапуск BB и откат с политикой `read`. При откате прежний маршрут вновь читает исходники, а запуск отладки отклоняется под действующей политикой. Хеши существующих параметров, навыка и справочника совпали. Тестовые данные доступа отсутствуют в CLI-статусах и установленных пакетах.

Проверка встроенного рантайма использовала проверенные артефакты Unica 0.16.0 из предыдущего прогона после прерывания зависшей холодной загрузки. Проверка перехода выполнялась изолированно от основного профиля и рабочих информационных баз. В основном профиле отдельным чтением подтверждены режим `external` и восемь регистраций у `bb-unica`. [Отложенный вызов](verification-3.2.md) подтверждён отдельным прогоном.

## Холодная подготовка рантайма

На Windows x64 вывод прогресса официального bootstrap Unica 0.16.0 превышал лимит буфера. Плагин теперь читает stderr потоком и сохраняет только окончание вывода для диагностики. После исправления `scripts/smoke.ts` загрузил все три артефакта в новый кэш, прочитал разные версии одноимённого модуля из двух Git worktree и подтвердил, что правка применяется только в согласованном worktree. Политика `read`, отсутствие подтверждения и попытка перенести его в другой worktree заблокировали запись.

## Публичный выпуск v0.1.0

Выпуск `v0.1.0` привязан к коммиту `64e202b2f53bb374358f90737ed83bee2871ca6e`. До открытия репозитория проверены файлы трёх коммитов: проверка путей и шаблонов учётных данных не выявила совпадений. В архиве релиза с production-зависимостями BB собрал app, server и host. TypeScript и семь тестов прошли локально и на CI для Windows и Ubuntu. [Выпуск](https://github.com/fokusov/bb-plugin-unica/releases/tag/v0.1.0) · [GitHub Actions](https://github.com/fokusov/bb-plugin-unica/actions/runs/45655095164)

На изолированном BB 0.50.1 кандидат запущен вместе с `1c-properties` `v0.1.0-rc.2`, `openspec-bsl-flow` `v0.6.2` и `memory-reflection` `v0.1.3`. Передача владения активировала восемь инструментов BB после двух перезагрузок. Ранний откат блокировался, после отключения `bb-unica` встроенный режим восстановился. При возврате во внешний режим все четыре компонента получили `running`.

В новом профиле BB Git-учётные данные не использовались. Каталог комплекта разрешил запись `bb-unica` в публичный тег `v0.1.0` и точный коммит выпуска. Плагин получил `running`, BB принял app bundle и зарегистрировал восемь агентских инструментов.

У опубликованного плагина в этом профиле `unica prepare` загрузил три официальных артефакта. RPC диагностики подтвердил готовность Unica 0.16.0, инициализацию MCP, каталог из 11 инструментов и чтение синтетической конфигурации через `unica.view`.
